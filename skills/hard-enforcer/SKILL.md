# 执行纪律

本 Skill 不产出内容，只做一件事：**在每一步拦住自己。**

它的每一条都对应代码层的一道闸门。对应关系写在条目末尾 ——
找得到闸门的条目是硬约束，找不到的属于习惯建议。

---

## 一、动笔之前

```
□ 本次分析要用的数据源，逐条列出，并写下各自覆盖哪些语义
□ 核验每个源是否已登记、是否有资格覆盖声明的语义
□ 核验必需语义（营收、净利）是否都有源承接
```

**未登记的数据源，禁止出现在分析计划与结论中。**
不是「尽量不要」，是「拒绝」。

> → `GATE-01` / `GATE-05`

---

## 二、数据进入分析时

```
□ 每个数值是否携带：数值 / 量纲 / 币种 / 频率 / 语义 / 时点 / 来源
□ 是否存在查不到就直接填 0 的地方
□ 是否存在「来源不明」的数值
□ 数据的时点是否在时效窗口内
```

三条禁止：

| 禁止 | 正确做法 |
|---|---|
| 用 0 填充缺失 | 显式标记为缺失，说明原因 |
| 不写时点 | 每个数值标注 `as_of` |
| 来源写「网络」 | 来源必须是已登记的数据源标识 |

> → `GATE-02` / `GATE-03` / `GATE-41` / `GATE-42`

---

## 三、每完成一个阶段，自检

### P0 之后

```
□ 一句话定义里有没有「赋能」「生态化」「全链路」「一站式」「闭环」
   → 有则重写，这些词只是掩盖了没说清的事实
□ 分业务拆解是否 ≥2 条，占比合计是否为 1.0
□ 加权毛利率与整体毛利率的偏差是否在 2 个百分点以内
   → 超出说明拆解口径不自洽
□ 目标价是否为区间形式
```

> → `GATE-10` / `GATE-11` / `GATE-54`

### P2 之后

```
□ 产业链是否拆到 ≥7 层
□ 每层是否写的是具体工序，而不是「XX行业」「XX领域」
□ 每层是否标注了单台/单件价值量
□ 排除矩阵是否 ≥5 家，且每家都有实质排除理由
□ 产能→收入桥梁的五个字段是否齐全
   （设备台数 / ASP / 交付率 / 验收率 / 单位）
```

> → `GATE-12` / `GATE-13` / `GATE-14`

### P3 之后

```
□ 三表勾稽是否平衡：资产 = 负债 + 权益
□ 预测年数是否 ≥5
□ 分业务收入加总是否等于整体营收（偏差 <2%）
□ 法务会计模型的结果是否附带了各自的局限说明
```

> → `GATE-20` / `GATE-21`

### P4 之后

```
□ 本阶段是否出现了「我们认为」「我们的判断」「应该」等结论性表述
   → 有则删除。此阶段只提问
□ 非共识论点是否 ≥2 条，且每条都能被事实推翻
□ 高证据等级的空头论据条数，是否 ≥ 多头
   → 少于多头说明空头是走过场
□ 反事实推理是否含 if / then / 可观测指标 三要素
```

> → `GATE-15` / `GATE-16` / `GATE-23`

### P5 之后

```
□ 反向 DCF 是否执行，且是否收敛
□ 是否给出了目标价 → 反向 DCF 不应产出目标价
□ 估值锚是否 ≥2 个，离散度是否在 80% 以内
□ 每个锚是否注明了方法
□ 正向 DCF 是否披露了终值占比
```

> → `GATE-43` / `GATE-50` / `GATE-51`

### P6 之后

```
□ 是否声明了持有周期与对应的主导决策模块
□ 尺度冲突是否都已裁决
□ 仓位上限是否 ≤25%，环境评级是否允许开新仓
□ 止损价是否低于入场价，单笔风险是否在可接受范围
```

> → `GATE-22` / `GATE-52` / `GATE-53`

---

## 四、发布之前

```
□ 状态声明是否已生成（PASS / DRAFT_REVIEW / BLOCKED）
□ 若为 BLOCKED，是否已删除全部结论段
□ 所有数值是否都能追溯到已登记的数据源
□ 报告中的闸门通过情况是否与实际一致
```

**BLOCKED 时不得输出任何结论、估值或操作建议。**
只输出阻断原因清单。

> → `GATE-40`

---

## 五、永远不要做的事

以下是历史上真实出过问题的地方，列在这里作为最后一道提醒：

| 不要做 | 因为 |
|---|---|
| 用通用网页检索获取估值倍数 | 实测口径偏差可达 +76% ~ +265% |
| 让非结构化源提供财务数字 | 它在结构上就不该有这个资格 |
| 把「查不到」当成「是 0」 | 两者完全不同，且后者的错误会传播到底 |
| 只用一个估值锚下结论 | 不同方法可能相差两倍，只报一个等于选择性地呈现 |
| 用「跳过闸门」的开关图方便 | 这个开关三个月后会出现在所有运行里 |
| 在 P4 给结论 | 会被前序分析锚定，形成循环论证 |
| 让空头章节比多头弱 | 那是自我确认，不是风险揭示 |

## 与代码层的关系

本清单中的自检项，全部有对应的程序化闸门。
Skill 层的作用是**让模型知道自己在被检查什么**，从而倾向于一次做对；
真正执行拦截的是代码层。

两者不可互相替代：

- 只有代码，模型会反复试错，浪费轮次
- 只有 Skill，约束依赖自觉，而自觉不可靠

---

## 关于「例外」

本清单没有例外条款。

如果某条要求在当前场景下确实不适用，正确的做法是**修改规则本身**
并在 `docs/engineering/adr/` 记录原因，而不是本次跳过。
跳过一次就会跳过第二次 —— 这条经验来自实践，不是设计洁癖。
