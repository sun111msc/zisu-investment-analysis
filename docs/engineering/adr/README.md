# 架构决策记录（ADR）

记录**做了什么决定**，以及**否决了什么、为什么否决**。

第二点比第一点更重要。任何一份代码都能看出「最终选了什么」，
但看不出「当时考虑过什么、为什么没选」。而这恰恰是判断工程成熟度的关键：
一个没有否决记录的仓库，通常意味着没有认真比较过备选方案。

## 格式

```markdown
# NNNN. 决策标题

- 状态：提议 / 已采纳 / 已废弃 / 已被 NNNN 取代
- 日期：YYYY-MM-DD
- 影响：高 / 中 / 低

## 背景
遇到什么问题

## 决策
选了什么

## 备选方案
还考虑过什么，各自的问题

## 后果
这个决定带来的好处与代价（都要写）

## 否决记录
明确否决的方向与理由
```
