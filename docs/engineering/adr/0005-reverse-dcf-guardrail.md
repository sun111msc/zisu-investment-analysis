# 0005. 反向 DCF 作为校验工具而非定价工具

- 状态：已采纳
- 日期：2026-08-30
- 影响：高

## 背景

正向 DCF 的问题是它的输出被当作结论使用，但它本质上是一个假设的包装。

敏感性分析显示：在典型参数下，终值占企业价值的 **60%-85%**。
也就是说，那个精确到小数点后两位的「目标价」，
大部分来自对永续增长率的一个假设。

把假设包装成数字有两个后果：

1. **伪精确**。使用者以为得到的是客观结果，实际上是自己假设的回声。
2. **不可证伪**。「目标价 41.2 元」这个判断，除了等股价走到那里，
   没有别的方式检验它对不对。

## 决策

把反向 DCF 作为估值环节的**必做项**，并施加两条接口层面的约束：

### 约束一：不产出目标价

`ReverseDCFResult` 里没有价格字段，只有：

```
converged / implied_g / implied_wacc / note
```

这不是「不写文档」，而是**结构上不给**。用例
`test_reverse_dcf_does_not_emit_price_target` 会断言
`to_gate_payload()` 的键集合里不含任何 price / target 字段。

### 约束二：不收敛就是结论

如果市值高于任何合理参数下的企业价值，返回 `converged=False` +
`bounds_hit=True`，并给出解释：

> 市值高于最乐观假设下的价值 —— 现金流假设无法解释当前市值，
> 需考虑反身性溢价或市场错误定价

这比强行给一个巨大的隐含增速更有信息量。
前者告诉使用者「你的估值框架解释不了它」，
后者给出一个看起来精确、实际无意义的数字。

## 为什么这样更好

反向 DCF 把问题从「值多少钱」变成了「要做到什么」。

- 正向：「我认为它值 41.2 元」→ 观点，无法检验
- 反向：「当前市值要求永续增速 8.7%、折现率 10%」→ 事实约束

后者立刻产生可检验的问题：**8.7% 的永续增速可信吗？**
对照历史增速、同业水平、产能规划，这个问题有答案。

同时它把假设的责任交还给使用者：折现率是你给的、
现金流预测是你给的，反解只是把这些假设与市值对上。
假设不合理，反解结果会立刻变得荒谬 —— 这就是校验。

## 备选方案

**方案 A：继续只用正向 DCF，但强制披露终值占比。**
比原来好，但没有解决「目标价不可证伪」的问题。

**方案 B：用蒙特卡洛给出估值分布。**
解决了单点假设问题，但输出是一条分布曲线，
使用者仍会取中位数当目标价。问题被转移而非解决。

**方案 C：只做反向 DCF，不做正向。**
过度。正向 DCF 在「检验自身假设一致性」上仍有价值，
只要不把它当成定价输出。

**方案 D：反向 DCF 也输出目标价（作为「市场隐含价」）。**
这会立刻被当作目标价使用。既然无法阻止误用，就从接口上杜绝。

## 后果

**好处**：
- 估值环节的输出从「观点」变成「可检验的约束」
- 不收敛本身成为有价值的信息（反身性溢价信号）
- 与多锚交叉（`GATE-51`）配合，构成完整的估值纪律

**代价**：
- 使用者需要改变习惯 —— 不再拿到一个数字，而是拿到一组隐含参数
- 反解需要市值数据，缺市值时该闸门失败（`GATE-50`）
- 二分法在极端参数下可能不收敛，需要给出清晰的失败原因而非静默失败

## 否决记录

**否决「把隐含 g 转成隐含市盈率再输出」。** 这等于换了个名字输出目标价，
绕过了本条 ADR 的核心约束。

**否决「收敛失败时返回最接近的解」。** 「最接近的解」会掩盖
「市值无法被现金流假设解释」这一重要信号。
