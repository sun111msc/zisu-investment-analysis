# 架构

## 一句话

把股票深度分析做成一条**契约驱动、失败关闭**的流水线：
每个数字携带七属性契约，每道纪律是一段可执行代码，每次失格都显式可见。

## 分层

```
┌────────────────────────────────────────────────────────────────┐
│  接口层    cli.py · casefile.py                                 │
│            场景 JSON → 上下文装配；命令行入口                     │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌────────────────────────────────────────────────────────────────┐
│  编排层    pipeline/orchestrator.py                             │
│            八阶段顺序执行 · 两轮闸门调用 · 状态定稿               │
├────────────────────────────────────────────────────────────────┤
│  阶段层    pipeline/phases.py                                   │
│            P0 画像 → P1 行业 → P2 穿透 → P3 财务 →              │
│            P4 市场 → P5 估值 → P6 执行 → P7 裁决                │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌────────────────────────────────────────────────────────────────┐
│  领域层    valuation/ · forensic/ · chains/                     │
│            反向 DCF · 四法务会计模型 · 产业链瓶颈分级             │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌────────────────────────────────────────────────────────────────┐
│  治理层    gates/                                               │
│            25 道闸门 · 五阶段质控 · 失败即失败关闭               │
├────────────────────────────────────────────────────────────────┤
│  数据层    datasources/                                         │
│            登记门禁 · 多级降级链 · 取数审计                       │
├────────────────────────────────────────────────────────────────┤
│  基础设施  contracts/ · observability/                          │
│            类型化数值契约 · 三态输出 · 执行轨迹                   │
└────────────────────────────────────────────────────────────────┘
```

**依赖单向**：上层依赖下层，下层不知道上层的存在。
`contracts` 不依赖任何内部模块；`datasources` 只依赖 `contracts`；以此类推。

## 数据流

一次分析的数据流只有一条路径，没有旁路：

```
场景 JSON
   │
   ├─▶ 能力清单（CapabilityManifest）  ← 动笔前先声明用哪些源、覆盖哪些语义
   │        │
   │        └─▶ 【GATE-01】未登记 / 越权 → 直接拒绝，分析不开始
   │
   ├─▶ 降级链取数（L0 → L1 → L2）
   │        │
   │        ├─▶ 每次数值产出 TypedValue（七属性）
   │        ├─▶ 每次尝试写审计日志
   │        └─▶ 全败 → 显式缺失值（不是 0）
   │
   ├─▶ 八阶段执行
   │        │
   │        └─▶ 阶段之间只通过 artifacts 通信
   │
   ├─▶ 第一轮闸门（数据 / 深度 / 逻辑）
   │        │
   │        └─▶ 中间状态声明 → 写回 artifacts
   │
   ├─▶ 第二轮闸门（格式 / 判断，含状态声明自身的校验）
   │
   └─▶ 定稿状态声明（PASS / DRAFT_REVIEW / BLOCKED）
            │
            └─▶ BLOCKED 时不输出结论段
```

## 三个关键设计

### 1. 为什么是「正金字塔」而不是「市场认知先行」

如果先讨论市场共识，后续所有分析都会被这个共识锚定 —— 你会不自觉地
去寻找支持既有结论的证据，形成循环论证。

因此流水线强制：**先建立独立的业务事实（P0-P3），再去问市场是不是错了（P4）。**
在这之前，任何「我们认为」都是禁止的（对应穿透铁律一）。

### 2. 为什么闸门是代码而不是提示词

写在提示词里的约束是「提醒」：模型可以权衡、可以觉得这次不一样、可以忘。
写在代码里的约束是「门禁」：不满足就无法继续。

这个区别在实践中是决定性的。一次真实事故中，模型为省事用通用检索去估
滚动市盈率，口径偏差达 +76% ~ +265% —— 而提示词里明明写着「禁止」。
改造为编译期登记门禁后，同类问题不再出现，因为**根本没有这条路径**。

### 3. 为什么反向 DCF 不产出目标价

DCF 的输出对永续假设高度敏感，终值常占企业价值的 60%-85%。
正向 DCF 给出的「目标价」，本质上是把自己的假设包装成了数字，
而任何单点假设都缺乏信息量。

反向 DCF 把球踢回给市场：**市值现在要求这家公司未来做到什么？**
如果反解出「需要连续十年维持 35% 增速」，那这就变成了一个可以被事实
检验的问题，而不是一个可以被争论的观点。

因此本项目的反向 DCF 在接口层面就没有「价格」字段 —— 见
`tests/unit/test_valuation.py::test_reverse_dcf_does_not_emit_price_target`。

## 目录职责

| 路径 | 职责 | 不做什么 |
|---|---|---|
| `src/zisu/contracts/` | 数值契约、三态输出 | 不做计算、不访问外部 |
| `src/zisu/datasources/` | 登记门禁、降级链、审计 | 不判断数值好坏 |
| `src/zisu/gates/` | 25 道规则 + 五阶段调度 | 不修改产物、不给结论 |
| `src/zisu/pipeline/` | 阶段协议与编排 | 不做领域计算 |
| `src/zisu/valuation/` | DCF、反向 DCF、可比 | 不决定买不买 |
| `src/zisu/forensic/` | 四个法务会计模型 | 不做结论判定 |
| `src/zisu/chains/` | 产业链分级与仓位映射 | 不评估具体公司 |
| `src/zisu/observability/` | 执行轨迹 | 不拦截任何东西 |

## 扩展点

| 想做的事 | 改哪里 |
|---|---|
| 接入自己的数据源 | 实现 `DataSource` 协议 + 在注册表登记 |
| 加一道闸门 | `gates/rules.py` 加规则 + `ALL_RULES` 登记 + 更新 `docs/engineering/gate-catalog.md` |
| 加一个阶段 | 继承 `Phase` + 在 `default_phases()` 插入 |
| 换一种估值锚 | `Phase5Valuation` 里加 anchor，`GATE-51` 会自动校验多锚 |
| 增加评测样本 | 在 `examples/cases/` 或 `evals/injections.py` 加一条 |
